# 08 - Area plan for the uxtheme conformance corpus

Role: area planner. Inputs: docs/research/01..07, tools/uxtheme_exports.{txt,json}. Output: `tools/areas.json` (30 areas, array of `{a,d}`) consumed by the corpus-creation workflow. Each `d` is a dense scope brief for the test author (functions, flags, HRESULTs, decomp offsets, themed vs themeless expectations).

## Principles

* Theme-state detection first: every test calls IsThemeActive/IsAppThemed and tries OpenThemeData(NULL,L"Button"); themed-only checks `t_skip` when it fails. Theme-independent behaviour (E_POINTER/E_HANDLE ordering, window props, buffered paint, parent background, dark-mode globals, COM exports) and the themeless contract are hard CHECKs. Recorded numbers (part sizes, colors, metrics) are `t_note` only unless proved in decomp.
* Facts come from 02_win10_semantics (decomp, tagged [V]) and 01_consumers (comctl32 call sites). Items marked UNVERIFIED/UNKNOWN in the descriptions must be read in decomp before being hard-checked. Nothing here was run on Windows.
* Process-global mutations (SetThemeAppProperties, SetPreferredAppMode) run in child processes (`t_spawn_child`). Machine-mutating ordinals (14, 65, 92, 97, 101-102, 122-123, 130 ...) live only in `theme_loader_destructive` / `immersive_color_ordinals` under the dx_ tag.
* comctl32 consumer areas need a v6 activation context (tools/probe_ctl6.manifest) and a v5 child-process counterpart (no manifest).

### open_close_handles

HTHEME lifetime and encoding. HTHEME is (generation<<16)|slot, not a pointer (CThemeApiHelper::OpenHandle @0x18888): assert handle low 16 bits nonzero, high bits >=1 on first open, t_note the numeric value only. Two OpenThemeData(hwnd,L"Button") on the same hwnd/dpi return the SAME handle (OpenRenderObject cache reuse) and need two CloseThemeData; second Close of the pair succeeds, third returns E_HANDLE 0x80070006. CloseThemeData(NULL)=E_HANDLE, CloseThemeData(garbage 0xDEADBEEF)=E_HANDLE, CloseThemeData does not touch GetLastError (preset sentinel 0x5A5A before call, check unchanged). Use-after-close: every handle-taking getter returns E_HANDLE (generation check) - 20-iteration open/close loop then stale-handle reuse must never succeed (generation increments, wraps 0xFFFF->1 not testable). OpenThemeData on success sets LastError 0 (SetLastError(hr) with hr=0) - preset 0x1234 then check 0. OpenThemeData removes the hwnd's old 0xa912 prop BEFORE opening, so GetWindowTheme(hwnd) returns the newest handle and, after a FAILED reopen with class L"NoSuchClass", returns NULL (old handle not closed, still valid for getters). GetWindowTheme(NULL) and GetWindowTheme(destroyed hwnd) -> NULL with LastError 0x80070006. OpenThemeData with hwnd==NULL is legal and does not set a window prop. Handles survive WM_THEMECHANGED / SetThemeAppProperties(0) (existing HTHEMEs stay valid; they hold a ref on the old theme file) - themed only. Cross-thread: handle opened on thread A usable from thread B (global render list under critical section). Themeless contract (inactive): every OpenThemeData returns NULL, CloseThemeData of anything E_HANDLE. Verify in decomp: CRenderList::CloseRenderObject @0x19048, _OpenThemeData @0x192c4, GetWindowTheme @0x6a10.
